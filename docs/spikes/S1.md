# S1: variable-height message list under resize and prepend

Issue: #57. Run on 3 November 2026 against gpuicn 0.8.0 `MessageList`, which
wraps GPUI Kit 0.9.0 `MessageScroller` on `gpui-pre` 0.3.11's `list`.

Code: `spikes/s1`. The headless measurements are `cargo test -p spike-s1 --
--nocapture --test-threads=1` (GPUI's test platform, real layout and text
shaping, no GPU). The interactive window for the reference machine is `cargo
run -p spike-s1 --release --features runtime_shaders`.

The transcript is 50,000 rows: messages of 1 to 20 lines, a third of the lines
long enough to wrap below about 900px, one row in eight with a 200px image
placeholder, a day divider every 500 rows and sender grouping in runs of four.
The window is 1200×800.

## The scrollbar

GPUI's `list` counts a row that has never been measured as 0px tall. The
scrollbar is drawn from the measured rows only, so with 50,000 rows and a few
hundred measured, the scrollbar describes a transcript a few thousand pixels
long. Measured with a raw `ListState` set up the same way as
`MessageScrollerState` (top alignment, tail follow, 400px overdraw), because
the Kit state keeps its `ListState` private:

| Step | Thumb top (fraction of track) | Thumb length | Content height the scrollbar uses |
| --- | --- | --- | --- |
| Jump to row 25,000 | 0.138 | 0.252 | 3,170px |
| Scroll down 4,000px | 0.620 | 0.112 | 7,164px |
| Prepend 200 rows | 0.620 | 0.112 | 7,164px |
| Resize to 600px | 0.316 | 0.395 | 2,027px |

So the thumb tracks how much has been measured, not where the reader is:

- Scrolling through a few screens of a 50k-row channel moves the thumb by half
  the track, and its length keeps changing.
- A width change clears every cached height (`list.rs` prepaint: "If the width
  of the list has changed, invalidate all cached item heights"), so the thumb
  jumps and shrinks back to the few rows on screen.
- Prepended rows add 0px until they scroll into view, then the thumb shifts.

The anchor itself is safe because `ListState::splice` shifts the anchor's item
index and keeps its pixel offset, and a width change keeps the item index and
offset as well. Only the scrollbar is wrong.

## What this means for Matty

- History paging, tail-follow, jump-to-latest and resize are sound on
  gpuicn 0.8.0. The message list work (#98) can go ahead on `MessageList`.
- The scrollbar is the gap. In practice Matty holds a window of a few hundred
  to a few thousand posts per channel, not 50k, which makes the error smaller
  but not gone. Fixing it belongs upstream, not in Matty. Options, roughly in
  order of preference:
  1. GPUI's `list` estimates unmeasured rows from the average measured height
     instead of 0px, so the thumb is roughly right from the start.
  2. On a width change, keep the old heights as size hints (or scale them)
     until rows are measured again, instead of dropping them.
  3. Kit's `MessageScrollerState` exposes an opt-in `measure_all`; that is
     correct but measures every row, which is too slow for long channels.
  4. As a fallback, gpuicn's `MessageList` hides the scrollbar thumb until
     the content is measured, or shows only the jump pill and the position
     indicator.
- Frame timing still needs a run on the reference Mac before #57 can close.
